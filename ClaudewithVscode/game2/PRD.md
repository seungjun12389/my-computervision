## 1. 개요

### 1.1 제품 정의

키보드로 지렁이를 조종해 먹이를 먹으며 몸을 늘리고, 벽과 자기 몸을 피해 최대한 오래 살아남아 높은 점수를 노리는 싱글 플레이 아케이드 게임.

### 1.2 목적

- 한 판에 1~3분이면 끝나는, 규칙 설명이 필요 없는 즉시 플레이 가능한 게임을 제공한다.
- "최고 점수 경신"이라는 단일 동기로 반복 플레이를 유도한다.
- Pygame의 게임 루프·상태 관리·충돌 판정을 명확한 구조로 보여주는 학습용 레퍼런스 역할도 겸한다.

### 1.3 대상 사용자

| 사용자 유형 | 니즈 |
| --- | --- |
| 캐주얼 플레이어 | 설치 후 바로, 설명 없이 즐길 수 있을 것 |
| 파이썬 학습자 | 읽고 수정하기 쉬운 코드 구조, 기능별로 분리된 모듈 |

### 1.4 성공 기준

- 처음 실행한 사용자가 별도 안내 없이 30초 이내에 첫 판을 시작하고 조작할 수 있다.
- 게임 재실행 후에도 이전 최고 점수가 유지되어 표시된다.
- 게임 진행 중 조작 지연이나 프레임 끊김이 체감되지 않는다.
- 10장의 검수 체크리스트를 100% 통과한다.

## 2. 범위

### 2.1 In Scope (이번 버전에 포함)

- 그리드 기반 지렁이 이동 및 방향 전환
- 먹이 생성·섭취·성장
- 벽 충돌 / 자기 몸 충돌에 의한 게임오버
- 점수 계산 및 최고 점수 로컬 영속화
- 먹이 섭취 수에 따른 자동 속도 증가 (난이도 상승)
- 일시정지 / 재개
- 시작 화면 · 일시정지 화면 · 게임오버 화면
- 게임오버 후 재시작 및 종료

### 2.2 Out of Scope (이번 버전에서 제외)

| 제외 항목 | 사유 |
| --- | --- |
| 멀티플레이 (로컬·온라인) | 단일 플레이 완성도에 집중 |
| 온라인 랭킹 / 서버 연동 | 네트워크 인프라 불필요, 로컬 최고 점수로 충분 |
| 모바일·웹 이식 | 데스크톱 Pygame 실행형에 한정 |
| 특수 아이템 (부스터, 감속, 무적 등) | 핵심 규칙의 명료함 우선 |
| 장애물 / 스테이지 / 맵 에디터 | 11장 향후 확장으로 이월 |
| 사운드 / BGM / 효과음 | 11장 향후 확장으로 이월 |
| 벽 통과(워프) 모드 | 기본은 벽 충돌 = 사망으로 고정 |

## 3. 게임 규칙 (핵심 메커니즘)

### 3.1 필드

- 플레이 필드는 **30열 × 20행**의 격자이며, 셀 하나는 **20px × 20px**이다.
- 따라서 플레이 영역은 600px × 400px이고, 상단에 40px 높이의 HUD가 붙어 창 전체 크기는 **600px × 440px**이다.
- 좌표계는 셀 단위 정수 `(col, row)`를 사용하며 좌상단이 `(0, 0)`이다.

### 3.2 지렁이

- 지렁이는 셀 좌표의 순서 있는 목록으로 표현하며, 리스트의 첫 원소가 **머리**다.
- 게임 시작 시 필드 중앙에서 길이 **3**, 진행 방향 **오른쪽**으로 시작한다.
- 렌더링(60 FPS)과 무관하게, **고정 틱** 주기마다 정확히 한 칸씩 이동한다.
- 이동은 진행 방향으로 새 머리를 추가하고 꼬리를 제거하는 방식이다. 먹이를 먹은 틱에는 꼬리를 제거하지 않아 길이가 1 늘어난다.

### 3.3 방향 입력

- 방향키(↑↓←→) 또는 WASD로 방향을 바꾼다.
- **180도 역주행은 금지**한다. 길이가 2 이상인 상태에서 현재 진행 방향의 정반대 방향 입력은 무시된다. (오른쪽으로 가는 중 ← 입력 → 무시)
- 한 틱 안에 여러 키가 눌려도 **틱당 방향 전환은 1회**만 확정된다. 이는 입력 큐로 처리한다: 눌린 키는 순서대로 큐에 쌓이고, 틱마다 큐에서 하나를 꺼내 유효한(역주행이 아닌) 방향이면 적용한다.
  - 이 규칙이 없으면 "오른쪽 → ↑ → ← "를 한 프레임에 빠르게 입력했을 때 위로 꺾이기도 전에 왼쪽이 적용되어 자기 목을 물고 즉사하는 버그가 발생한다.

### 3.4 먹이

- 필드에는 항상 먹이가 정확히 **1개** 존재한다.
- 먹이는 지렁이 몸통이 점유하지 않은 빈 칸 중 **균등 확률로 무작위 선택**된 위치에 생성된다.
- 지렁이의 머리가 먹이 칸에 도달하면 섭취로 판정하고, 길이 +1, 점수 증가 후 즉시 새 먹이를 생성한다.

### 3.5 충돌 및 종료

- **벽 충돌**: 머리의 다음 좌표가 필드 밖(`col < 0`, `col >= 30`, `row < 0`, `row >= 20`)이면 게임오버.
- **자기 몸 충돌**: 머리의 다음 좌표가 자기 몸통 좌표와 겹치면 게임오버.
  - 단, 이동으로 비워질 **꼬리 끝 칸**은 충돌로 보지 않는다. 그 칸에 진입하는 것은 허용된다. (먹이를 먹어 꼬리가 유지되는 틱에서는 꼬리 끝도 충돌 대상이다.)
- **필드 포화(클리어)**: 지렁이 길이가 전체 셀 수(600)와 같아져 더 놓을 빈 칸이 없으면 승리로 판정하고, 게임오버 화면에 "CLEAR" 문구와 함께 결과를 표시한다.
- 이 게임에는 시간 제한이나 사망 이외의 패배 조건이 없다.

### 3.6 점수와 난이도

- 먹이 1개당 **10점**.
- 시작 속도는 **초당 8틱**이다.
- 먹이를 **5개** 먹을 때마다 속도가 **초당 1틱** 증가한다.
- 속도 상한은 **초당 20틱**이며, 도달 후에는 더 증가하지 않는다.
- HUD의 속도 레벨은 `Lv 1`에서 시작해 속도가 오를 때마다 1씩 증가한다 (최대 `Lv 13`).

## 5. 게임 상태 흐름

```
        [시작]
           │
           ▼
      ┌─────────┐  SPACE/ENTER   ┌───────────┐
      │  MENU   │───────────────►│  PLAYING  │
      └─────────┘                └───────────┘
           ▲                       │   ▲   │
         R │                   P/Esc│   │P/Esc
           │                       ▼   │   │ 충돌/클리어
      ┌───────────┐             ┌────────┐ │
      │ GAME_OVER │◄────────────│ PAUSED │ │
      └───────────┘             └────────┘ │
           ▲                               │
           └───────────────────────────────┘
```

### 5.1 상태 전이표

| 현재 상태 | 입력 / 조건 | 다음 상태 | 부수 효과 |
| --- | --- | --- | --- |
| MENU | `SPACE` / `ENTER` | PLAYING | 게임 상태 초기화 (점수 0, 길이 3, 시작 속도) |
| MENU | `Q` / 창 닫기 | (종료) | — |
| PLAYING | `P` / `ESC` | PAUSED | 틱 타이머 정지 |
| PLAYING | 벽 충돌 또는 자기 충돌 | GAME_OVER | 최고 점수 갱신 및 저장 |
| PLAYING | 필드 포화 | GAME_OVER | 클리어 판정, 최고 점수 갱신 및 저장 |
| PAUSED | `P` / `ESC` | PLAYING | 틱 타이머 재개 |
| GAME_OVER | `R` | PLAYING | 게임 상태 완전 초기화 |
| GAME_OVER | `Q` / 창 닫기 | (종료) | — |

### 5.2 상태별 입력 처리 원칙

- 방향 입력은 **PLAYING 상태에서만** 큐에 적재된다. PAUSED·GAME_OVER 중 눌린 방향키는 무시되며, 재개 시 남아 있지 않는다.
- 창 닫기(`QUIT`) 이벤트는 모든 상태에서 최우선으로 처리한다.

## 6. 화면 / UI 요구사항

### 6.1 레이아웃

```
┌──────────────────────────────────────────────┐
│ SCORE: 120      BEST: 350            Lv 3    │  ← HUD (600 × 40)
├──────────────────────────────────────────────┤
│ · · · · · · · · · · · · · · · · · · · · · ·  │
│ · · · · · · · ● · · · · · · · · · · · · · ·  │  ● 먹이
│ · · · · ▣ ▢ ▢ · · · · · · · · · · · · · · ·  │  ▣ 머리  ▢ 몸통
│ · · · · · · · · · · · · · · · · · · · · · ·  │
│ · · · · · · · · · · · · · · · · · · · · · ·  │  ← 플레이 필드
│ · · · · · · · · · · · · · · · · · · · · · ·  │     (600 × 400 = 30 × 20 셀)
└──────────────────────────────────────────────┘
```

### 6.2 색상 팔레트

| 용도 | 색상 | RGB |
| --- | --- | --- |
| 배경 (플레이 필드) | 짙은 남색 | `(18, 22, 32)` |
| 그리드 선 | 어두운 회청색 | `(30, 36, 50)` |
| HUD 배경 | 더 짙은 남색 | `(12, 15, 22)` |
| 지렁이 머리 | 밝은 연두 | `(120, 230, 120)` |
| 지렁이 몸통 | 초록 | `(60, 170, 90)` |
| 먹이 | 주황빨강 | `(235, 90, 70)` |
| 기본 텍스트 | 밝은 회색 | `(225, 228, 235)` |
| 강조 텍스트 (NEW RECORD 등) | 노랑 | `(245, 200, 70)` |
| 오버레이 | 검정 반투명 | `(0, 0, 0, 180)` |

### 6.3 표현 세부

- 각 셀은 셀 크기보다 1~2px 작은 사각형으로 그려 셀 간 경계가 자연스럽게 드러나게 한다.
- 머리는 몸통과 다른 색을 사용하며(FR-30), 진행 방향 쪽에 눈을 나타내는 작은 점 2개를 선택적으로 그릴 수 있다.
- 폰트는 Pygame 기본 폰트(`pygame.font.SysFont`)를 사용한다. HUD 18px, 화면 제목 48px, 안내 문구 20px.
- 일시정지·게임오버 화면은 플레이 화면을 지우지 않고 그 위에 반투명 오버레이를 덮는 방식으로 표시한다(FR-14, FR-31).

## 7. 조작 방식

### 9.2 모듈 책임

| 모듈 | 책임 | 주요 인터페이스 |
| --- | --- | --- |
| `config.py` | 모든 상수의 단일 출처 | `GRID_COLS`, `GRID_ROWS`, `CELL_SIZE`, `HUD_HEIGHT`, `INITIAL_TPS`, `TPS_STEP`, `MAX_TPS`, `FOODS_PER_LEVEL`, `SCORE_PER_FOOD`, `COLORS` |

### 9.3 메인 루프 구조

```python
# main.py — 개념 코드
clock = pygame.time.Clock()
while running:
    dt = clock.tick(60) / 1000.0        # 초 단위 경과 시간

    for event in pygame.event.get():    # 1) 입력
        game.handle_event(event)

    game.update(dt)                     # 2) 업데이트
    renderer.draw(screen, game)         # 3) 렌더
    pygame.display.flip()
```

`Game.update(dt)`는 `PLAYING` 상태에서만 시간을 누적한다.

```python
# game.py — 고정 틱 누적
self._accumulator += dt
tick_interval = 1.0 / self.tps
while self._accumulator >= tick_interval:
    self._accumulator -= tick_interval
    self._tick()        # 방향 확정 → 이동 → 충돌 → 섭취 → 속도 갱신
```

이 구조 덕분에 프레임률과 게임 속도가 분리되고(8장), 속도 레벨은 `self.tps` 값만 바꾸면 즉시 반영된다.

### 9.4 한 틱의 처리 순서

1. 방향 큐에서 하나를 꺼내 유효하면 진행 방향으로 확정 (FR-5)
2. 다음 머리 좌표 계산
3. 벽 충돌 검사 → 해당 시 GAME_OVER (FR-13)
4. 먹이 섭취 여부 판정 (`next_head == food.position`)
5. 자기 충돌 검사 — 섭취하지 않은 경우 꼬리 끝은 제외 (FR-8, FR-9)
6. 이동 수행 (섭취 시 꼬리 유지 → 성장) (FR-6, FR-7)
7. 섭취했다면 점수 가산, 먹이 재배치, 속도 갱신 (FR-12, FR-16, FR-18)
8. 빈 칸이 없으면 클리어 판정 (FR-15)
